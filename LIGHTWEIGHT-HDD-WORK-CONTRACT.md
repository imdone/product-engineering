# Lightweight HDD Work Contract

Use this contract when a team is using different coding plugins or skills on the same story and the work does not need the full HDD workflow.

## Core Surface

- Problem
- Current Plan
- Progress notes in `attachments/progress-notes.md`

## Contract

1. Read the story and progress notes before planning or editing.
2. Keep the core surface to Problem, Current Plan, and the Progress notes attachment.
3. Add extra artifacts only when risk, ambiguity, review, or handoff requires them.
4. Capture a minimum success measure before planning: observable outcome, feedback path, and evidence/data-capture mechanism.
5. Stop at the plan checkpoint before implementation; continue only after the evaluated plan is explicitly approved.
6. Record deploy evidence, outcome evidence, decisions, blockers, corrections, and meaningful completed work in the story or attachments, not only in chat.

## Optional Template

The lightweight template is optional. When used, it should stay sparse: Problem, Current Plan, a Progress notes link, and Closeout.

Full HDD remains the better default for high-risk, ambiguous, provider-sync-sensitive, or cross-team work.
